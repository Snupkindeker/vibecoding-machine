## Reporting a Vulnerability

We appreciate your help in keeping this project secure. If you discover a security vulnerability, please follow these steps:

### 📌 Do NOT:
- **Do NOT** use GitHub Issues to report security vulnerabilities.
- **Do NOT** publicly disclose the vulnerability before it is fixed.

### ✅ What to do:
1. **Send your report** to **snupkindeker@yandex.ru** or via Telegram: [@bedwarsskill](https://t.me/bedwarsskill).
2. **Include as much detail as possible:**
   - Description of the vulnerability.
   - Steps to reproduce it.
   - Potential impact and exploitation scenarios.
   - Any possible fixes or mitigation suggestions.
3. **Expect a response within 72 hours**.
4. **If your report is accepted**:
   - The vulnerability will be fixed within **30 days** (depending on complexity).
   - You will be credited for the discovery (if you wish).
5. **If your report is declined**:
   - You'll receive a clear explanation why.
   - The vulnerability will not be addressed in the near future.

## Scope

This policy applies to:
- All code in this repository.
- Dependencies and third-party components used in the project.
- Docker images and deployment configurations.

---

## Responsible Disclosure

We follow a responsible disclosure process:
- We will publicly acknowledge the report after the fix is released.
- We will credit the reporter (unless they prefer to remain anonymous).

---

## Security Tips for Users

- Always use the latest version of the project.
- Keep your `GITHUB_PAT`, `AI_API_KEY`, and other secrets **private**.
- Never commit `.env` files or any secrets to version control.
- Use the portable version or Docker images from trusted sources only.
